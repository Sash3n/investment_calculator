Vercel + Firebase Deploy Guide

For Vite + React apps — FinCalc ZA reference · compiled from real mistakes

1

Set up Firestore security rules Firebase

Firestore created in production mode defaults to deny all. Set rules before your first deploy or nothing will save.

Firebase Console → Firestore Database → Rules tab

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
  }
}
Tip: Click Publish after pasting — just editing the box doesn't save it.
2

Import the project on Vercel Vercel

  1. Go to vercel.com → sign in with GitHub
  2. Click Add New → Project → find your repo → Import
  3. Vercel auto-detects Vite — leave all build settings as-is: 
    Framework:        Vite
Build Command:    npm run build
Output Directory: dist
  4. Do not click Deploy yet — add environment variables first (Step 3)
3

Add environment variables Vercel

Expand Environment Variables before clicking Deploy. Copy values from your .env.local file.

Variable Correct value
VITE_FIREBASE_API_KEY Your API key from Firebase config
VITE_FIREBASE_AUTH_DOMAIN your-project-id.firebaseapp.com
⚠️ This is the Firebase domain — NOT your Vercel URL
VITE_FIREBASE_PROJECT_ID e.g. fincalc-za
VITE_FIREBASE_STORAGE_BUCKET your-project-id.firebasestorage.app
VITE_FIREBASE_MESSAGING_SENDER_ID Number from Firebase config
VITE_FIREBASE_APP_ID App ID from Firebase config
After any env var change you must redeploy: Vercel → Deployments → ··· → Redeploy. Changes don't apply to existing deployments automatically.
4

Whitelist your Vercel domain in Firebase Firebase

Google sign-in is blocked from any domain not on the authorised list — including your Vercel URL.

  1. Firebase Console → Authentication → Settings → Authorised domains
  2. Click Add domain
  3. Enter your Vercel URL exactly — no https://, no trailing slash: 
    your-app-name.vercel.app
  4. Takes effect immediately — no redeploy needed
Custom domain? Add it here too — each domain you use to access the app must be listed separately.
!

Common mistakes & fixes

MISTAKE 1

VITE_FIREBASE_AUTH_DOMAIN set to the Vercel URL

Setting VITE_FIREBASE_AUTH_DOMAIN to your-app.vercel.app instead of the Firebase project domain. This causes auth/unauthorized-domain and a 404 on /__/auth/iframe.

✓ FIX

Always set it to your Firebase project domain:
your-project-id.firebaseapp.com
Found in Firebase Console → Project Settings → Your apps → Config object.

MISTAKE 2

Firestore left in production mode (deny all)

When you create a Firestore database in production mode, ALL reads and writes are blocked by default. Saves appear to work (no visible error) but nothing persists — the error is swallowed silently.

✓ FIX

Paste the security rules from Step 1 into Firestore → Rules and click Publish before testing any data operations.

MISTAKE 3

Changing domain but not updating Firebase authorised domains

Renaming or changing your Vercel project URL (e.g. from app-chi-ten.vercel.app to app-za.vercel.app) invalidates the old Firebase whitelist entry. Sign-in immediately breaks with auth/unauthorized-domain.

✓ FIX

Every time you change domains: Firebase Console → Authentication → Settings → Authorised domains → Add the new URL. Keep the old one until you're sure nothing uses it.

MISTAKE 4

Changing env vars without redeploying

Updating an environment variable in Vercel's dashboard only applies to future deployments. The currently live deployment still uses the old values.

✓ FIX

After any env var change: Vercel → Deployments → click ··· on the latest → Redeploy. Takes ~60 seconds.

MISTAKE 5

Silent Firestore errors (no user feedback)

Using try/finally without a catch block means Firestore permission errors are swallowed. The UI shows no feedback and the user has no idea why their save didn't work.

✓ FIX

Always add a catch block that surfaces the error in the UI. Check for permission-denied in the error message to give a specific hint about Firestore rules.

✓

Pre-deploy checklist

  • ✓ npm run build passes with no TypeScript errors locally
  • ✓ Firestore security rules published (not left as deny-all)
  • ✓ VITE_FIREBASE_AUTH_DOMAIN = your-project.firebaseapp.com (NOT the Vercel URL)
  • ✓ All 6 Firebase env vars added to Vercel before first deploy
  • ✓ Vercel domain added to Firebase Authorised Domains
  • ✓ After any env var change → redeploy on Vercel
  • ✓ Test Google sign-in on the live URL in an incognito window after deploy
  • ✓ If you rename the Vercel project → re-add the new URL to Firebase Authorised Domains
